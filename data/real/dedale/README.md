# METHODOLOGICAL INFORMATION 
 
## Environmental/experimental conditions: 

DEDALE is a dataset designed for the evaluation of intrusion detection systems
(IDS). It is focused on the detection of an APT-like attack; it contains both
network and host data, allowing the evaluation of network IDS and host IDS. It
also contains a long period of time with only benign activity, that allows to
train unsupervised anomaly-based IDS.

The entire system was virtualized on a single server. It is composed of about 40
virtual machines (clients and servers) with different operating systems (Windows
and Linux). The system was connected to the Internet so as to include browsing
activity. The dataset lasts four weeks. The first two weeks contain only benign
activity and can be used to train unsupervised anomaly-based IDS. An APT-like
attack begins on the third week and lasts 8 days. The normal activity is
generated by Aura (https://dedale.inria.fr/user_behavior.html and
https://gitlab.inria.fr/mlanvin/aura).

You can find more informations here: https://dedale.inria.fr/

## Description of sources and methods used to collect and generate data:

### Network data

Network data was captured at different capture points of the IT system. This can
be useful to evaluate the detection capabilities depending on the capture point.
There are one capture point in each zone of the IT system (green_internal,
orange_servers and orange_dmz, see https://dedale.inria.fr/rescousse.html for
the architecture of the IT system). Traffic is also captured on the central
router of the IT system (Company Router 1) on each of its network interfaces.

The pcap files were cut with pyCapCutter to ensure that all the packets of a
network connection are in the same file
(https://gitlab.inria.fr/mlanvin/pycapcutter).

After that, we also processed the pcap files with Zeek (https://zeek.org/) and
CICFlowMeter (corrected version of CICFlowMeter:
https://github.com/GintsEngelen/CICFlowMeter).

Each router of the IT system runs a Suricata NIDS. We also provide the alerts
raised by both instances Suricata.

### Host data

For Linux computers, we provide syslog and auditd logs. The configuration for
auditd can be found in the RESCOUSSE gitlab project:
https://gitlab.inria.fr/mlanvin/rescousse/-/blob/main/provisioning/ansible/roles/auditbeat/).

For Windows computers, we provide the logs sent by Winlogbeat (the configuration
of Winlogbeat is here:
https://gitlab.inria.fr/mlanvin/rescousse/-/tree/main/provisioning/ansible/roles/configure_intcompanyclient_win10/files/winlogbeat).
Among the logs, there are Sysmon logs (the configuration for Sysmon is here:
https://gitlab.inria.fr/mlanvin/rescousse/-/tree/main/provisioning/ansible/roles/configure_intcompanyclient_win10/files/sysmon).

All logs are sent to the Elastic log server in the orange_servers zone. There are then extracted from the server in the JSON format.

### Label data

We label network and host data using the methodologies described in the article
and on the website (https://dedale.inria.fr/download.html), and the programs here: https://gitlab.inria.fr/mlanvin/dedale_labeling

# DATA & FILE OVERVIEW
 
## File naming convention:

For preprocessed network data, we use the name of the zone (green_internal,
orange_servers, orange_dmz) or router1 in the name of the file so as to provide
the information on the capture point. For example, "zeek_router1.zip" contains all the Zeek logs for the Company Router 1.

For the raw network data, we also use the name of the zone but for the Company
Router 1, we provide the raw pcap file by network interface. We also split data
by week and use this in the name of the file. For example,
"router1_green_week3.zip" contains the pcap files captured on the green
interface of the Company Router 1 for the thrid week. Each zip file contains a
pcap file by day for the week.

The suricata alerts raised by the Suricata NIDS running on each router are
provided in "suricata_alerts.zip".

For the host logs, they are split by the source provider: winlogbeat, auditbeat,
syslog and packetbeat. Each file contains the logs for all the computers for the
four weeks.

We also provide the logs from AURA (the normal activity generation tool):
"userbehaviour_logs.zip".

The labels for the evaluation are provided in the "system_logs_labels.zip" for
host data and in the Zeek logs for network data (conn.log files).
